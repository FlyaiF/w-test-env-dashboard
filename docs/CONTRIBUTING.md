# 文档维护规范

> Status: current
> Scope: repository-owned documentation; excludes vendored files and the zipr submodule

## 目录和职责

| 载体 | 记录内容 | 不承担的职责 |
| --- | --- | --- |
| 根 README | 工程组成、启动入口、文档导航 | 全量操作手册 |
| 根 / 局部 AGENTS.md | 对对应目录修改时必须遵守的约束、按任务阅读入口 | 任务进度和历史讨论 |
| 模块 README | 该模块的前提、运行、生成、验证与排错入口 | 复制全局架构叙述 |
| CONTEXT.md | 领域术语、关系含义与易混淆词 | 实现方案和开发步骤 |
| CONTEXT-MAP.md | 当前上下文关系、代码归属 | 尚未实施的架构承诺 |
| docs/guides/ | 当前行为、配置、操作、限制和代码导航 | 已过期的实施步骤 |
| docs/adr/ | 有真实取舍、改变成本较高且原因不直观的决定 | 普通拆文件、日常修复 |
| docs/plans/ | 有限范围的进行中计划、验收条件 | 永久事实来源 |
| docs/plans/archive/ | 已结束或已被替代的计划及其历史上下文 | 新任务清单 |
| docs/research/ | 有日期和来源的研究快照、未采纳方案 | 当前约束或待实现承诺 |
| docs/prototypes/ | 设计试验；由关联文档标明采纳结果 | 生产实现 |
| docs/releases/ | 面向用户的版本变化 | 开发进度与架构说明 |

小型待办使用 Issue；只有需要在仓库内持续交接时才创建计划文件，不为凑齐目录创建空文档。

## 格式

使用 Markdown，每篇一个一级标题，标题与正文、列表之间留空行。新增说明优先使用中文，
保留代码中的规范英文术语；无需仅为统一语言重译历史文档。

指南、模块 README 和计划使用以下简短头部；按实际需要添加日期：

```markdown
# 标题

> Status: current
> Scope: 适用模块或能力
> Reviewed: YYYY-MM-DD (说明核对范围，例如仅核对代码，未做运行验收)

简述用途，并链接权威来源或上级索引。
```

状态约定：`current` 表示当前指南；`proposed` / `active` 表示计划阶段；`archived` 表示
历史计划；`snapshot` 表示研究时点。归档时写 `Archived` 日期和当前承接文档；研究写
`Recorded` 日期，外部版本、统计和 issue 状态只代表该时点。
发布说明遵循[发布说明约定](releases/README.md)，可直接使用列表，不强制一级标题，
不添加会出现在用户更新弹窗里的治理元数据。
`CONTEXT.md` 保持纯词汇表，`CLAUDE.md` 保持对 AGENTS 的引用；两者不强加状态模板。

ADR 使用 `NNNN-slug.md` 连续编号，简短说明背景、选择和理由即可。顶部状态为
`proposed`、`accepted`、`partially-superseded`、`superseded` 或 `deprecated`。
替代时列出后继文档，明确失效的部分和仍生效的约束，保留原始理由；不把历史决定改写成
“当初就这样决定”。补录既有决定时区分原决定时间与记录时间。

功能指南通常包含：当前行为与限制、配置或使用方法、关键代码和验证入口。
计划通常包含：问题证据、目标、非目标、步骤、验收条件、未解决事项和承接文档。
不强制填充无内容的章节。

## 来源和维护规则

1. 同一事实选择一个维护位置，其他文档链接它。工具链版本以 CI、依赖清单为准；配置以
   配置文件为准；发布版本以 env_viewer 的 pubspec 为准。文档解释含义，不复制易漂移的全表。
2. 更改行为时同步当前指南；更改领域含义时同步词汇表；改变重要取舍时更新 ADR 替代关系。
   更改目录时同步索引、相对链接和源码注释中的文档路径。
3. 完成或放弃计划后归档，提取仍有效的规则到指南或 ADR。区分“实现已存在”和“验收已通过”，
   不把本机路径、旧分支或过去的测试结果作为后来协作者的前提。
4. 若代码和有效文档冲突，先核对依据并说明差异；代码能证明当前行为，不能单独证明设计意图。
   历史计划、研究建议和原型不得自动升级为当前要求。
5. 记录生产配置时使用占位符，不记录凭证或本机专属数据。局部行为理由就近写代码注释，
   跨模块约束用链接指向指南或 ADR。

## 提交前核对

- 新文档已加入索引，状态与实际阶段一致。
- 仓库内引用使用相对链接；移动后核对链接、锚点和源码注释，无旧路径残留。
- 当前指南与有效 ADR 不互相矛盾；历史内容有明显标识和当前承接文档。
- 命令写清执行目录；已区分推荐检查、CI 实际执行的检查和本次确实运行的检查。
- 仅文档整理检查 diff 与链接即可；涉及行为修改时按[开发验证指南](guides/development.md)执行检查。
